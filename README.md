# Простой мессенджер

Представиться → выбрать собеседника → переписываться. Вся переписка **сохраняется
навсегда** в одном файле базы данных (SQLite) на сервере.

Здесь лежат готовые файлы для запуска на сервере через **Dokploy**.

---

## Что внутри

| Файл | Зачем он |
|---|---|
| `server.js` | «Мозг»: хранит людей, чаты и сообщения, отдаёт их браузеру. |
| `public/index.html` | Страница мессенджера (то, что видно в браузере). |
| `public/style.css` | Внешний вид. |
| `public/app.js` | Поведение кнопок и сообщений. |
| `package.json` | Список «деталей», которые нужны серверу. |
| `Dockerfile` | Объясняет Dokploy, как собрать и запустить мессенджер. |
| `docker-compose.yml` | Вариант запуска через Docker Compose (с постоянным хранилищем). |

Данные хранятся в папке, указанной в переменной `DATA_DIR` (по умолчанию `/app/data`).
Именно **эту папку важно подключить к постоянному хранилищу**, иначе при обновлении
сервера переписка исчезнет.

## Как выложить на Dokploy (по шагам)

### Шаг A. Положить код в GitHub
Dokploy забирает код из Git-репозитория.

1. Создай пустой репозиторий на GitHub (например, `messenger`).
2. Загрузи туда файлы из этой папки (можно через сайт GitHub кнопкой «Add file»).

### Шаг B. Создать приложение в Dokploy

1. Открой панель Dokploy.
2. **Create Project** → назови, например, `Messenger`.
3. Внутри проекта: **Create Application**.
4. Вкладка **General** → **Provider**: выбери `GitHub`, затем свой репозиторий и ветку `main`.
5. **Build Type**: `Dockerfile` (Dokploy увидит `Dockerfile` сам).

### Шаг C. Указать порт

В настройках приложения найди поле **Port** и укажи **3000**
(это тот порт, на котором работает наш мессенджер).

### Шаг D. Подключить постоянное хранилище (важно!)

Чтобы переписка не пропадала:

1. Открой вкладку **Volumes** (или **Mounts**) у приложения.
2. Добавь новое хранилище:
   - **Name**: `messenger-data`
   - **Mount Path** (куда подключить внутри): `/app/data`
3. Сохрани.

### Шаг E. Переменные окружения (по желанию, обычно не нужно)

Во вкладке **Environment** можно задать:

```
PORT=3000
DATA_DIR=/app/data
```

Значения по умолчанию уже такие, поэтому этот шаг можно пропустить.

### Шаг F. Домен и HTTPS

1. Вкладка **Domains** → **Add Domain**.
2. Введи свой домен (например, `chat.твойсайт.ru`).
3. **Container Port**: `3000`.
4. Включи **HTTPS** (Certificate Provider: `Let's Encrypt`).
5. Сохрани.

> Нужно, чтобы домен уже «смотрел» на IP твоего сервера (настройка A-записи
> у регистратора домена). Если не получится с первого раза — это самая частая
> заминка, не пугайся.

### Шаг G. Запустить

Нажми **Deploy** (или **Redeploy**). Dokploy сам:
1. скачает код,
2. соберёт мессенджер,
3. запустит его,
4. поднимет сайт на твоём домене.

Через минуту-две открывай `https://твой-домен` — увидишь экран «Представься».
Позови друзей: они открывают ту же ссылку, создают своё имя и находят тебя в списке «Все люди».

## Как проверить локально (если есть Docker)

На своём компьютере, в этой папке:

```
docker compose up --build
```

Потом открой `http://localhost:3000`.

Если Docker нет — ничего страшного, можно сразу деплоить в Dokploy.

## Как это работает простыми словами

- **Представиться** — человек вводит имя и пароль. Пароль хранится зашифрованным.
- **Выбрать собеседника** — список всех людей; нажатие создаёт чат.
- **Сообщения** — сохраняются в базу и подгружаются при входе.
- **Обновление в живую** — браузер каждые 2 секунды тихонько спрашивает сервер
  «нет ли нового?». Поэтому сообщения появляются сами.

## Безопасность (что уже сделано)

- Пароли хранятся **зашифрованными** (bcrypt), не в открытом виде.
- Читать переписку может **только** её участник (сервер это проверяет).
- Текст сообщений выводится безопасно, чтобы никто не мог «подсунуть» вредный код.
